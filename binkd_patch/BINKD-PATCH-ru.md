# Добавление к Binkd поддержки новых форматов бинарных логов посредством патча исходного кода в файле `binlog.c`

## Собственный бинарный лог Binkd, задаваемый параметром `binlog`

Мейлер Binkd сохраняет информацию о проведённых сессиях в бинарном логе, заданном параметром `binlog` в конфигурационном файле. Например:
```
binlog /home/user/fido/logs/binkd.sts
```
Этот файл имеет формат бинарного лога T-Mail до версии 2603 (старый формат T-Mail). Достоинством этого формата является небольшой размер записей &ndash;
28 байт на сессию. Недостатки бинарного лога Binkd следующие:

- Отметка направления сессии (входящая или исходящая) у Binkd противоположна тому, как сессии отмечает T-Mail.
Поэтому в конфигурационном файле `T-Hist` необходимо указывать параметр `SwapInOut Yes` для бинарных логов Binkd.

- Если сессия завершилась с ошибкой (например, была оборвана), то информация о направлении сессии в бинарном логе Binkd теряется. Поэтому
приходится принудительно задавать в конфигурационном файле `T-Hist` направление оборванных сессий с помощью параметра `BinkdAborted`.

- Не сохраняются данные о том, была ли сессия защищена паролем или нет. `T-Hist` для бинарных логов Binkd не способен генерировать статистику
по парольным и непарольным сессиям.

- Нет возможности сохранить в бинарном логе IP-адрес FTN системы, с которой выполняется сессия, её доменное имя, FTN имя, локацию и другие
данные, получаемые во время хэндшейка.

Но есть способ, полностью сохраняя функционирование "родного" бинарного лога Binkd, одновременно записывать информацию о сессиях в бинарный лог
другого формата, обладающего расширенными возможностями.

## Логи, задаваемые параметрами `fdouthist`/`fdinhist`

В штатном примере конфигурационного файла Binkd рядом с параметром `binlog` есть закомментированные строки:
```
# Uncomment if you want FrontDoor-style binary log
#
#fdinhist in.his
#fdouthist out.his
```

Чтобы разобраться, как именно происходит запись таких логов, если эти параметры раскомментировать, я изучил файл `binlog.c` из репозитория
[Binkd](https://github.com/pgul/binkd) на GitHub (https://github.com/pgul/binkd/blob/master/binlog.c). Мои выводы следующие:

1. Это не формат лога FrontDoor, а формат лога Bink/+. Программный код в функции `FDLogStat()` записывает в бинарный лог данные в формате,
описанном в FAQ по Bink/+ ([http://faqs.org.ru/softw/fidosoft/bink_pls.htm](http://faqs.org.ru/softw/fidosoft/bink_pls.htm)),
в точности соответствующем тем структурам данных, которые использует `T-Hist` при обработке логов Bink/+.

    А настоящий формат FrontDoor можно посмотреть в официальном DevKit:
	```
	curl -O https://defsol.com/files/fddoc/fddev230.zip
	unzip fddev230.zip && unzip c.zip && cat MAILHIST.H
	```

2. В этом логе (который якобы FrontDoor, а на самом деле Bink/+) нет информации о том, нормально ли завершилась сессия или была оборвана, и нет отметки,
была ли сессия защищена паролем или нет. Поэтому особых преимуществ у него по сравнению с "родным" логом Binkd нет.

3. Можно в файле `binlog.c` изменить код так, чтобы лог, заданный параметром `fdouthist`/`fdinhist`, записывался в другом формате с расширенными возможностями.
При этом код, отвечающий за запись "родного" бинарного лога Binkd не будет никак затронут.

## Патчи для файла `binlog.c`

В итоге я сделал два патча для файла `binlog.c` (находятся в каталоге [binkd_patch](../binkd_patch)), позволяющие использовать следующие форматы для бинарного лога,
заданного параметром `fdouthist`/`fdinhist`:

  - [binlog-tmail.patch](binlog-tmail.patch) &ndash; использовать новый формат T-Mail;
  - [binlog-thist.patch](binlog-thist.patch) &ndash; использовать собственный формат `T-Hist`.

Оба этих формата содержат информацию о том, была ли сессия защищена паролем или нет, и позволяют корректно отмечать оборванные сессии. Также записи
в этих форматах могут содержать текстовую информацию о FTN системах, которую `T-Hist` способен выводить в режиме широкого экрана.
Подробнее об особенностях этих форматов можно прочитать в файле [ADD-NEW-MAILER-ru.md](../ADD-NEW-MAILER-ru.md).

Патчи изменяют только файл `binlog.c` и не затрагивают накакие другие исходные файлы Binkd. С применёнными патчами Binkd успешно компилируется под Linux.
Возможность компиляции под другие системы я не проверял.

Корректность работы Binkd, скомплированного с применением патча [binlog-tmail.patch](binlog-tmail.patch), проверена на узле 2:5020/715 (Alex Barinov). Примеры статистики, созданной
на основе бинарного лога патченного Binkd, находятся в файлах [example.out](example.out) и [example.lnk](example.lnk) в каталоге [binkd_patch](../binkd_patch).
IP-адреса в статистике изменены.

Корректность работы Binkd, скомплированного с применением патча [binlog-thist.patch](binlog-thist.patch), проверена на моём узле 2:5020/378.

## Выбор патча

Выбирайте патч с форматом `T-Hist`, если:

  - у вас трафик за одну сессию может превышать 4 гигабайта (формат `T-Hist` имеет 64-битные значения для трафика, в то время как у других форматов эти значения 32-битные,
не способные корректно сохранить данные о трафике, превышающем 4 гигабайта);

  - вы хотите видеть больше текстовой информации о FTN-системах при генерации статистики в режиме широкого экрана.

Выбирайте патч с форматом T-Mail, если:

  - вам достаточно для отображения в статистике не более 63 символов информации о FTN-системах, или вы вообще отключаете в `T-Hist` режим широкого экрана;

  - вы хотите сэкономить на размере бинарного лога.

## Инструкция по использованию патчей

1. Клонируйте репозиторий Binkd:

    `git clone https://github.com/pgul/binkd`

2. Перейдите в каталог с исходниками:

    `cd binkd`

3. Скопируйте сюда один патч под тот формат бинарного лога, который вам нужен.

4. Примените патч:

    `git apply binlog-thist.patch`

    или

    `git apply binlog-tmail.patch`

    При желании посмотрите пропатченный файл `binlog.c`

5. Скомпилируйте Binkd. Для компиляции под Linux выполните:

    `cp mkfls/unix/* .`

    `./configure`

    `make`

    Для компиляции под другие системы смотрите инструкции в репозитории Binkd.

6. В конфигурационном файле Binkd раскомментируйте один из двух параметров `fdouthist`/`fdinhist` (неважно какой) и укажите имя файла нового бинарного лога.
Если будут раскомментированы оба параметра, то будет использовано имя файла из `fdouthist`.

    Теперь если вы не закомментировали параметр `binlog`, Binkd будет записывать историю сессий и в собственный бинарный лог, и в новый.

7. Укажите новый бинарный лог в конфигурационном файле `T-Hist` для создания по нему статистики.
