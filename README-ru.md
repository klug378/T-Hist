# T-Hist для Linux и Windows

[![Visitors](https://visitor-badge.laobi.icu/badge?page_id=klug378.T-Hist)](https://github.com/klug378/T-Hist)

[![GitHub Last commit](https://img.shields.io/github/last-commit/klug378/T-Hist.svg?style=dark)](https://github.com/klug378/T-Hist)

Утилита `T-Hist` создаёт текстовые файлы с графиками и гистограммами загрузки узла FTN-сети и со статистикой по сессиям и линкам
за указанный интервал суток для заданных FTN-адресов (групп адресов). Информация о загрузке берется из файлов истории (бинарных логов) мейлеров.
`T-Hist` поддерживает форматы бинарных логов следующих мейлеров: Binkd, T-Mail, Argus, Internet Rex, FrontDoor, Bink/+, FhMail, 
BinkleyTerm-XE, The Brake!, KittenMail, DVMmail, XMail32, BasicMail, а также собственный формат бинарных логов (начиная с версии `1.4.0`).

Разработку `T-Hist` я начал в 1996 году. Последняя версия `T-Hist` `0.30.alpha7` для DOS, OS/2 и NT (win32) была выпущена в 2003 году.
Через 23 года я сделал новую версию `T-Hist`, а также сопутствующих утилит `LnkStat` и `DmpHist`, для Linux и Windows.

Утилиты распространяются в виде ZIP-архива, содержащего исполняемые файлы в следующих каталогах:
- `linux` – исполняемые файлы Linux для архитектур x86_64, i686 и arm64;
- `linux-static` – исполняемые файлы Linux для архитектур x86_64, i686 и arm64, скомпилированные со статическими библиотеками;
- `windows` – исполняемые файлы для Windows 64-bit и 32-bit.

Исполняемые файлы Linux, скомпилированные со статическими библиотеками, сжаты упаковщиком [UPX 4.2.4](https://upx.github.io) для уменьшения размера.

Полная документация на новую версию пока не готова. В качестве основы можно использовать документацию и пример конфигурационного файла
от версии `0.30.alpha7`, которые находятся в каталоге [doc_old_2003](./doc_old_2003) (кодировка текстовых файлов UTF-8).
Ниже будут рассмотрены отличия новых версий от старых.

Для использования в Linux конфигурационных файлов от старых версий, сконвертируйте их в Unix-формат:

```shell
dos2unix t-hist.ctl
```

Для сохранения русского текста в параметрах, имеющих текстовые значение, и в комментариях используйте кодировку UTF-8.

## Используемые ниже термины

- Под термином `старые версии` понимается версия `T-Hist` `0.30.alpha7`, выпущенная в 2003 году, и более ранние версии утилиты.

- Под термином `параметр` понимается параметр в конфигурационном файле. 

- Под терминами `группа`, `группа адресов` понимается адрес, заданный в параметре `Addr` с использованием хотя бы одного макроса `#`.
Адреса, заданные с использованием символов подстановки `*`, группами не являются.

- Термины `бинарный лог` и `файл истории` эквивалентны.

## Основные особенности новой версии

- Все утилиты выводят информацию и создают выходные текстовые файлы в кодировке UTF-8.
Для размещения статистики в русскоязычных эхоконференциях/нетмейле текстовые файлы необходимо преобразовать в кодировку CP866:

	```shell
	iconv -f UTF-8 -t CP866 in.txt -o out.txt
	```

  Дополнительно утилитам `LnkStat` и `DmpHist` (но не `T-Hist`) добавлена опция командной строки `-u` для выбора кодировки выводимой информации:
  - `-u`, `-u+` – использовать UTF-8 (по умолчанию);
  - `-u-` &emsp;&emsp;– использовать ASCII 7-bit без символов псевдографики.

- У всех утилит появился режим широкого экрана, разрешающий выводить строки длинее 80 символов. Этот режим включен по-умолчанию,
однако если вы обрабатываете бинарные логи старого формата (например, логи Binkd) и не задаёте комментарии (описания) к адресам в параметрах `Addr`,
то генерируемая статистика всё ещё будет иметь ширину не более 80 символов. Если же выполняется хотя бы одно из условий:
  - обрабатываемый бинарный лог содержит текстовую информацию о FTN-системах, с которыми проводились сессии, или информацию о протоколе
(это бинарные логи мейлеров: Internet Rex, FrontDoor, Bink/+, FhMail, BinkleyTerm-XE, KittenMail, The Brake!, некоторых мейлеров с логами в новом формате T-Mail,
а также бинарные логи собственного формата `T-Hist`);
  
  - хотя бы в одном из параметров `Addr` задан комментарий (описание) к адресу,
  
  то в режиме широкого экрана справа от графика загрузки и справа от таблиц со статистикой будет выводиться прочитанная из бинарного лога текстовая информация
или указанные в параметрах `Addr` комментарии (описания). Если для адреса существует одновременно и текстовая информация из бинарного лога, и комментарий (описание)
в параметре `Addr`, то приоритет имеет информация из бинарного лога.

  Для управления режимом широкого экрана добавлен параметр конфигурационного файла `WideScreen`
со следующими допустимыми значениями:
  - `WideScreen Yes` &ensp;– включить режим широкого экрана без ограничения длины выводимых строк;
  - `WideScreen No` &emsp;– выключить режим широкого экрана; длина всех выводимых строк будет не более 80 символов;
  - `WideScreen <N>` &ensp;– включить режим широкого экрана и установить длину выводимых строк не более `N` символов
  (`N` – целое число; если задать `N` меньше 80, то режим широкого экрана будет выключен, и длина строк будет ограничена 80 символами);
  - `WideScreen` &emsp;&emsp;– то же, что и `WideScreen Yes`.
  
  Значение параметра по-умолчанию: `WideScreen Yes`.

  Также всем утилитам добавлена опция командной строки `-w`:
  - `-w`, `-w+` – эквивалентны `WideScreen Yes`;
  - `-w-` &emsp;&emsp;– эквивалентно `WideScreen No`;
  - `-w<N>` &emsp;– эквивалентно `WideScreen <N>`.
	
- Все утилиты могут выводить значения трафика с использованием единиц измерения, основанных как на двоичных степенях, так и на десятичных.
В старых версиях однобуквенные обозначения `K`, `M` и `G` после значений трафика означали единицы измерения, основанные на двоичных степенях, то есть
`KiB` – 1,024 байт, `MiB` – 1,048,576 байт и `GiB` – 1,073,741,824 байт. В новых версиях появилась возможность выводить значения трафика в
`kB` – 1,000 байт, `MB` – 1,000,000 байт и `GB` – 1,000,000,000 байт.

  Для выбора единиц измерения в конфигурационный файл добавлен параметр `DecimalUnits` со следующими допустимыми значениями:
    - `DecimalUnits Yes` – использовать десятичные единицы измерения `kB`, `MB` и `GB`;
    - `DecimalUnits No` &ensp;– использовать двоичные единицы измерения `KiB`, `MiB` и `GiB`;
    - `DecimalUnits` &emsp;&ensp;– то же, что и `DecimalUnits Yes`.

  Значение по-умолчанию: `DecimalUnits No`. Таким образом, если этот параметр не задан, то приложения выводят значения по-старому, в двоичных единицах измерения.

  Чтобы не нарушать форматирование, обозначения величин в статистике остаются однобуквенными (`K`, `M`, `G`), а после суммарной информации выводится расшифровка,
означают ли они двоичные единицы измерения (`KiB`, `MiB`, `GiB`) или десятичные (`kB`, `MB`, `GB`).

  Также всем утилитам добавлена опция командной строки `-r`, соответствующая параметру `DecimalUnits`, со следующими допустимыми значениями:
  - `-r`, `-r+` – эквивалентны `DecimalUnits Yes`;
  - `-r-` &emsp;&emsp;– эквивалентно `DecimalUnits No`.

- Все утилиты могут работать без конфигурационного файла, если в командной строке задан хотя бы один файл бинарного лога.
Значения параметров обработки бинарного лога определяются следующими правилами:

  - Если конфигурационный файл не указан явно с помощью опции командной строки `-c`, и в текущем каталоге не был обнаружен конфигурационный файл с именем `t-hist.ctl`,
то будут обработаны заданные бинарные логи, а все параметры, которые не были заданы другими опциями командной строки, получат значения по-умолчанию.
(Таблица со значениями параметров по-умолчанию приведена ниже в этом документе.)

  - Если конфигурационный файл указан явно с помощью опции командной строки `-c`, или в текущем каталоге присутствует конфигурационный файл с именем `t-hist.ctl`,
то заданные бинарные логи будут обработаны совместно с логами из конфигурационного файла, а параметры, которые не были заданы другими опциями командной строки,
получат значения из конфигурационного файла. 

  Примеры:
  ```text
  t-hist  /home/user/fido/logs/binkd.sts
  t-hist  /home/user/fido/logs/binkd.sts -d-1 -t12-24 -bTIO$ -g -k -mg 
  t-hist  /home/user/fido/logs/binkd.sts -с/home/user/fido/config/t-hist.conf -w120
  lnkstat /home/user/fido/logs/binkd.sts -b1.9.2026 -e20.9.2026 -g 
  dmphist /home/user/fido/logs/binkd1.sts /home/user/fido/logs/binkd2.sts -w- -u-
  ```

- Порядок задания адресов с помощью параметров `Addr` неважен. Независимо от того, в каком порядке заданы адреса и группы адресов, при генерации статистики они будут отсортированы
от менее общих к более общим. При этом исключаемые адреса и группы адресов будут размещены в начале списка, попутно удаляя все адреса, совпадающие с исключаемой группой.
Повторные задания одних и тех же адресов будут игнорироваться. Например, если в конфигурационном файле указано:

	```
	Addr 2:5020/#.#
	Addr 2:5020/378.0
	Addr #:#/#.#
	Addr 2:5020/378.0
	Addr 2:#/#.#
	Addr 2:5020/1132.0
	Addr 2:5020/408.0
	Addr !2:5020/1132.*
	Addr !*:*/*.666
	Addr 2:5020/715.#
	Addr 2:5020/1132.0
	Addr !2:5020/408.0
	```

  то при генерации статистики будет использоваться вот такой список адресов:

	```
	Addr !2:5020/408.0
	Addr !2:5020/1132.*
	Addr !*:*/*.666
	Addr 2:5020/378.0
	Addr 2:5020/715.#
	Addr 2:5020/#.#
	Addr 2:#/#.#
	Addr #:#/#.#
	```

  Если в конфигурационном файле не задано ни одного параметра `Addr`, то при при генерации статистики будет использована группа по-умолчанию `Addr #:#/#.#`, охватывающая все адреса. 

- Если в группах адресов помимо макросов `#` есть символы подстановки `*`, то эти символы будут автоматически заменяться на макросы.
Символы подстановки могут присутствовать только в адресах, не являющихся группами. Например, следующий список адресов:

	```
	Addr 2:5020/378.*
	Addr 2:*/#.*
	```

  будет преобразован к виду

	```
	Addr 2:5020/378.*
	Addr 2:#/#.#
	```
	
  и в статистике будет одна общая строка для всех пойнтов узла `2:5020/378` и отдельные строки для других адресов из второй зоны, с которым были сессии.

- Новый алгоритм просмотра списка адресов, заданных параметрами `Addr`, при генерации статистики. В старых версиях просмотр списка адресов завершался после первого
совпадения адреса сессии с одним из адресов `Addr`. В новых версиях если адрес сессии не задан как исключаемый из статистики, просмотр будет продолжаться до конца списка.
Такой алгоритм позволяет учесть сессии с отдельно заданным адресом также и в статистике по группам, к которым принадлежит адрес. Например, для списка адресов

	```
	Addr !2:5020/1132.0
	Addr 2:5020/378.0
	Addr 2:5020/#.#
	Addr 2:#/#.#
	Addr #:#/#.#
	```

  сессии с адресом `2:5020/378.0` будут учтены не только в отдельной статистике для этого адреса, но и в групповой статистике сессий с адресами из сети `2:5020`,
в групповой статистике сессий с адресами из второй зоны и в групповой статистике сессий с любыми адресами. А сессии с адресом `2:5020/1132.0` будут игнорироватся.

- `T-Hist` и `LnkStat` присваивают длительность 1 секунда сессиям, прочитанным из бинарного лога с длительностью 0 секунд. Это позволяет корректно учитывать в статистике
короткие сессии, длившиеся меньше 1 секунды. Записанное в бинарный лог нулевое значение длительности таких сессий в возникает из-за того, что интервалы времени
задаются с точностью до секунды.
 
  Утилита `DmpHist` такую корректировку длительности сессий не делает. Эта утилита продолжает работать по-старому:
выводит сырые данные из бинарных логов без какой-либо корректировки. Для сессий короче секунды утилита выведет длительность 0 секунд, как записано в бинарном логе.

- В таблице сессий время начала сессий указывается с точностью до секунд (в старых версиях была точность до минут).
Время окончания сессий исключено по причине избыточности – в таблице приведена длительность сессий.

- Адреса FTN-узлов (то есть адреса с нулевым значением в поле `Point`), выводятся без окончания `.0` для улучшения читаемости статистики.
Пойнтовый номер выводится только если он имеет ненулевое значение. Данное изменение не затрагивает утилиту `DmpHist`.

- После таблиц сессий и после таблиц со статистикой по линкам и группам выводится суммарная информация о количестве сессий, их длительности и трафике.
Это точная копия информации, выводимой после графика загрузки и гистограмм.

- На гистограммах уровень загрузки больше 0%, но меньше 3% отображается с помощью символа `_`. В старых версиях из-за отсутствия подходящего символа псевдографики
такой уровень загрузки либо отображался избыточно большим – как уровень 3-10%, либо не отображался вообще.

- Утилита `DmpHist` не принимает во внимание параметр `TimeShift`, если он присутствует в конфигурационном файле, и выводит время начала сессий в точности так,
как оно записано в бинарном логе, без каких-либо корректировок.

- Утилита `DmpHist` выводит перед таблицей не только имя файла бинарного лога, но и информацию о его формате.
А после таблицы – более подробную расшифровку битов статуса сессий.

- Имена параметров в конфигурационном файле и их значения регистронезависимые за исключением имён файлов в Linux.

- Если параметр не задан ни в конфигурационном файле, ни через опцию командной строки, то он получит значение по умолчанию, приведённое в таблице:

  |    Параметр    | Значение по-умолчанию |
  | :------------- | :-------------------- |
  | `Output`       | `t-hist.out`          |
  | `LinkStat`     | `t-hist.lnk`          |
  | `SessionStat`  | `t-hist.ses`          |
  | `Date`         | сегодняшняя дата      |
  | `Time`         | `0:00:00-23:59:59`    |
  | `TimeShift`    | `0`                   |
  | `CutHistory`   | `0` (не обрезать лог) |
  | `Name`         | пустая строка         |
  | `Addr`         | `#:#/#.#`             |
  | `BinkdAborted` | `In`                  |
  | `ShowValue`	   | `Ses`                 |
  | `AdvancedCPS`, `WideScreen`,<br>`BusyHist` | `Yes` |
  | `Group`, `KeepAll`, `MiddLine`, `NoDrawZero`,<br>`ProtectSummary`, `BrakeSesStat`,<br>`SwapInOut`, `DecimalUnits` | `No` |

  (Есть отличия от значений по-умолчанию для старых версий.)

- Параметры `Addr`, `AdvancedCPS`, `BrakeSesStat`, `BusyHist`, `DecimalUnits`, `Group`, `KeepAll`, `MiddLine`, `NoDrawZero`, `ProtectSummary`,
`SwapInOut`, `WideScreen` в конфигурационном файле могут быть заданы без указания значения. В этом случае параметр `Addr` получит значение `#:#/#.#`,
а все остальные перечисленные параметры – значение `Yes`.

- Параметр `SupportNewFormat` объявлен устаревшим и игнорируется при чтении конфигурационного файла. Все форматы бинарных логов поддерживаются в полном объёме.

- Спецификаторы форматов, которые можно указывать при задании имён выходных файлов (в параметрах `Output`, `LinkStat`, `SessionStat` и соответствующих им
опциям командной строки `-o`, `-l`, `-e`, а также в опции `-o` утилиты `LnkStat`), приведены в соответствие со спецификаторами функции `strftime()`.
Допустимы следующие спецификаторы форматов:

  - `%Y` – год в четырехзначном формате (например, 2026);
  - `%y` – год в двузначном формате без века (от 00 до 99);
  - `%m` – номер месяца в виде десятичного числа от 01 до 12;
  - `%d` – день месяца в виде десятичного числа от 01 до 31;
  - `%j` – день года в виде десятичного числа от 001 до 366;
  - `%w` – день недели в виде десятичного числа от 0 до 6, где 0 – это воскресенье, 1 – понедельник, 6 – суббота;
  - `%u` – день недели в виде десятичного числа от 1 до 7, где 1 – это понедельник, 7 – воскресенье;
  - `%H` – час в 24-часовом формате от 00 до 23;
  - `%M` – минуты в виде десятичного числа от 00 до 59;
  - `%S` – секунды в виде десятичного числа от 00 до 59.

- В конфигурационном файле в качестве символа, начинающего комментарий, можно использовать не только унаследованный от старых версий символ `;`, но и более
привычный в linux-среде символ `#`. Особым случаем является обработка строки, содержащей параметр `Addr`. Такую строку можно закомментировать целиком,
поставив символ `#` перед `Addr`, но после `Addr` символ `#` будет уже считаться макросом для задания группы адресов, а не началом комментария.

- Изменена логика обработки опций командной строки `-g`, `-k`, `-n`. В старых версиях задание этих опции без следующего за ними знака `+` или `-` меняло значение
сответствующего параметра конфигурационного файла на противоположное. В новых версиях возможность инвертирования параметров убрана из-за малой востребованности,
а опция без следующего за ней знака `+` или `-` эквивалентна опции со знаком `+`.

- Опция командной строки `-h` используется для вывода справки по программе. Бинарные логи в командной строке задаются простым указанием имени файла.

- Утилитам `T-Hist` и `LnkStat` (но не `DmpHist`) добавлена опция командной строки `-z`, соответствующая параметру `TimeShift`, со следующими допустимыми значениями:
  - `-z` &nbsp;&emsp;– эквивалентно `TimeShift Auto` (сдвинуть время начала каждой сессии на разность между локальным временем и UTC, которая была в момент проведения сессии);
  - `-z<N>` – эквивалентно `TimeShift <N>` (сдвинуть время начала каждой сессии на `N` часов; `N` может быть отрицательным).

- Возможность обрезания бинарного лога при ненулевом значении параметра `CutHistory` реализована для логов следующих форматов/мейлеров: логи Binkd,
логи T-Mail старого и нового формата, логи KittenMail и логи всех версий собственного формата `T-Hist`. Для остальных поддерживаемый форматов обрезание не выполняется,
а параметр `CutHistory` игнорируется.

- Разработаны и полностью поддержаны всеми утилитами новые форматы бинарного лога (форматы `T-Hist`) с 64-битными значениями для входящего и исходящего
трафика, позволящие корректно сохранять информацию о сессиях, во время которых было отправлено или получено более 4 гигабайт.

  Недостатком форматов бинарных логов всех поддерживаемых утилитой `T-Hist` мейлеров является использование 32-битных величин для записи информации о трафике.
Форматы бинарных логов мейлеров разрабатывались в эпоху dial-up, когда передать более 4 гигабайт за одну сессию было практически нереально. Но в эпоху Fido-over-IP и
высокоскоростных сетей сессия с трафиком более 4 гигабайт – обычное явление, особенно на крупных раздающих хабах.

  Разработчикам FTN-мейлеров предлагается использовать бинарные логи собственных форматов `T-Hist` в своих программных продуктах. Помимо корректного сохранения
данных о сессиях с большими объёмами трафика, форматы позволяют сохранять текстовые строки, которые `T-Hist` может выводить в режиме широкого экрана
справа от графика загрузки и справа от таблиц со статистикой. Также форматы `T-Hist` позволяют записывать в бинарный лог отметку `Listed` для сессий,
FTN-адреса которых заданы в конфигурационных файлах мейлера или присутствуют в нодлистах, указанных в конфигурации мейлера.

  Подробно собственные форматы бинарного лога `T-Hist` рассмотрены в файле [ADD-NEW-MAILER-ru.md](ADD-NEW-MAILER-ru.md).

- Созданы патчи, позволяющие добавить к Binkd поддержку формата `T-Hist`. Находятся патчи в каталоге [binkd_patch](./binkd_patch). Подробнее читайте
в файле [BINKD-PATCH-ru.md](./binkd_patch/BINKD-PATCH-ru.md).

- Создана новая утилита: конвертер форматов бинарных логов `HistConv`. Утилита позволяет для заданного бинарного лога создать такой же лог в другом формате.
В качестве исходного может быть указан файл бинарного лога любого мейлера, поддерживаемого `T-Hist`. Формат исходного бинарного лога определяется автоматически.
Для выбора целевого формата используется опция командной строки `-f`, позволяющая указать один из следующих форматов:
  - собственный формат `T-Hist` первой и второй версий;
  - формат T-Mail версий 2603 и новее (новый формат T-Mail);
  - формат T-Mail до версии 2603 (старый формат T-Mail);
  - формат Binkd (старый формат T-Mail с инвертированной отметкой входящих/исходящих сессий).

  Если целевой формат не указан с помощью опции `-f`, то бинарный лог будет сконвертирован во вторую версию формата `T-Hist`.

  Для получения допустимых имён целевых форматов используйте справку по программе:
  ```shell
  histconv -h
  ```

## Как добавить поддержку нового мейлера

Чтобы использовать `T-Hist` вместе с мейлерами, которые он не поддерживает, необходимо сконвертировать логи мейлеров в один из форматов, понимаемых `T-Hist`.
Например, использовать формат бинарного лога Binkd, он же формат T-Mail до версии 2603 (старый формат T-Mail), формат бинарного лога T-Mail версий 2603 и новее
(новый формат T-Mail) или собственный 64-битный формат `T-Hist`. Подробнее читайте в файле [ADD-NEW-MAILER-ru.md](ADD-NEW-MAILER-ru.md).
