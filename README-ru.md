Утилита `T-Hist` создаёт текстовые файлы с графиками и гистограммами загрузки узла FTN-сети и со статистикой по сессиям и линкам
за указанный интервал суток для заданных FTN-адресов (групп адресов). Информация о загрузке берется из файлов истории (бинарных логов) мейлеров.
`T-Hist` поддерживает форматы бинарных логов следующих мейлеров: [Binkd](https://github.com/pgul/binkd), [qico 0.60.2+](https://github.com/glasslike/qico),
T-Mail, Argus, Internet Rex, FrontDoor, Bink/+, FhMail, BinkleyTerm-XE, The Brake!, KittenMail, DVMmail, XMail32, BasicMail, а также собственный формат
бинарных логов.

Разработку `T-Hist` я начал в 1996 году. Последняя версия `T-Hist` `0.30.alpha7` для DOS, OS/2 и NT (win32) была выпущена в 2003 году.
Через 23 года я сделал новую версию `T-Hist`, а также сопутствующих утилит `LnkStat` и `DmpHist`, для Linux и Windows.

## Структура распространяемого ZIP-архива с программой

Утилиты распространяются в виде ZIP-архива, содержащего исполняемые файлы в следующих каталогах:
- `linux` – исполняемые файлы Linux для архитектур x86_64, i686 и arm64;
- `linux-static` – исполняемые файлы Linux для архитектур x86_64, i686 и arm64, скомпилированные со статическими библиотеками;
- `windows` – исполняемые файлы для Windows 64-bit и 32-bit.

Исполняемые файлы Linux, скомпилированные со статическими библиотеками, сжаты упаковщиком [UPX 4.2.4](https://upx.github.io) для уменьшения размера.

В качестве руководства по программе используйте пример конфигурационного файла [t-hist.ctl](t-hist.ctl) с подробным описанием всех параметров,
и данный файл [README-ru.md](README-ru.md). Также для справки можно использовать старый файл документации от версии `0.30.alpha7`, который находится
в каталоге [doc_old_2003](./doc_old_2003). Кодировка текстовых файлов: UTF-8.

Для использования в Linux конфигурационных файлов от старых версий, сконвертируйте их в Unix-формат:

```shell
dos2unix t-hist.ctl
```
Для сохранения русского текста в параметрах, имеющих текстовые значение, и в комментариях используйте кодировку UTF-8.

## Возможности и особенности новых версий

### Используемые термины

- Под термином `старые версии` понимается версия `T-Hist` `0.30.alpha7`, выпущенная в 2003 году, и более ранние версии утилиты.

- Под термином `параметр` понимается параметр в конфигурационном файле. 

- Под терминами `группа`, `группа адресов` понимается адрес, заданный в параметре `Addr` или в опции командной строки `-a` с использованием
хотя бы одного символа подстановки `*`.

- Термины `бинарный лог` и `файл истории` эквивалентны.

### Внешний вид и оформление статистики

- Все утилиты выводят информацию и создают выходные текстовые файлы в кодировке UTF-8.
Для размещения статистики в русскоязычных эхоконференциях/нетмейле текстовые файлы необходимо преобразовать в кодировку CP866:

	```shell
	iconv -f UTF-8 -t CP866 in.txt -o out.txt
	```

  Дополнительно утилитам `LnkStat` и `DmpHist` (но не `T-Hist`) добавлена опция командной строки `-u` для выбора кодировки выводимой информации:
  - `-u`, `-u+` – использовать UTF-8 (по умолчанию);
  - `-u-` &emsp;&emsp;– использовать ASCII 7-bit без символов псевдографики.

- У всех утилит появился режим широкого экрана, разрешающий выводить строки длинее 80 символов. Этот режим включен по-умолчанию,
однако если вы обрабатываете бинарные логи старого формата (например, логи Binkd) и не задаёте комментарии (описания) к адресам в параметрах `Addr`,
то генерируемая статистика всё ещё будет иметь ширину не более 80 символов. Если же выполняется хотя бы одно из условий:
  - обрабатываемый бинарный лог содержит текстовую информацию о FTN-системах, с которыми проводились сессии, или информацию о протоколе
(это бинарные логи мейлеров: Internet Rex, FrontDoor, Bink/+, FhMail, BinkleyTerm-XE, KittenMail, The Brake!, некоторых мейлеров с логами в новом формате T-Mail,
а также бинарные логи собственного формата `T-Hist`);
  
  - хотя бы в одном из параметров `Addr` задано описание к адресу,
  
  то в режиме широкого экрана справа от графика загрузки и справа от таблиц со статистикой будет выводиться прочитанная из бинарного лога текстовая информация
или указанные в параметрах `Addr` описания адресов. Если для адреса существует одновременно и текстовая информация из бинарного лога, и описание
в параметре `Addr`, то приоритет имеет информация из бинарного лога.

  Для управления режимом широкого экрана добавлен параметр конфигурационного файла `WideScreen`
со следующими допустимыми значениями:
  - `WideScreen Yes` &ensp;– включить режим широкого экрана без ограничения длины выводимых строк;
  - `WideScreen No` &emsp;– выключить режим широкого экрана; длина всех выводимых строк будет не более 80 символов;
  - `WideScreen <N>` &ensp;– включить режим широкого экрана и установить длину выводимых строк не более `N` символов
  (`N` – целое число; если задать `N` меньше 80, то режим широкого экрана будет выключен, и длина строк будет ограничена 80 символами);
  - `WideScreen` &emsp;&emsp;– то же, что и `WideScreen Yes`.
  
  Значение параметра по-умолчанию: `WideScreen Yes`.

  Также всем утилитам добавлена опция командной строки `-w`:
  - `-w`, `-w+` – эквивалентны `WideScreen Yes`;
  - `-w-` &emsp;&emsp;– эквивалентно `WideScreen No`;
  - `-w<N>` &emsp;– эквивалентно `WideScreen <N>`.
	
- Все утилиты могут выводить значения трафика с использованием единиц измерения, основанных как на двоичных степенях, так и на десятичных.
В старых версиях однобуквенные обозначения `K`, `M` и `G` после значений трафика означали единицы измерения, основанные на двоичных степенях, то есть
`KiB` – 1,024 байт, `MiB` – 1,048,576 байт и `GiB` – 1,073,741,824 байт. В новых версиях появилась возможность выводить значения трафика в
`kB` – 1,000 байт, `MB` – 1,000,000 байт и `GB` – 1,000,000,000 байт.

  Для выбора единиц измерения в конфигурационный файл добавлен параметр `DecimalUnits` со следующими допустимыми значениями:
    - `DecimalUnits Yes` – использовать десятичные единицы измерения `kB`, `MB` и `GB`;
    - `DecimalUnits No` &ensp;– использовать двоичные единицы измерения `KiB`, `MiB` и `GiB`;
    - `DecimalUnits` &emsp;&ensp;– то же, что и `DecimalUnits Yes`.

  Значение по-умолчанию: `DecimalUnits No`. Таким образом, если этот параметр не задан, то приложения выводят значения по-старому, в двоичных единицах измерения.

  Чтобы не нарушать форматирование, обозначения величин в статистике остаются однобуквенными (`K`, `M`, `G`), а после суммарной информации выводится расшифровка,
означают ли они двоичные единицы измерения (`KiB`, `MiB`, `GiB`) или десятичные (`kB`, `MB`, `GB`).

  Также всем утилитам добавлена опция командной строки `-r`, соответствующая параметру `DecimalUnits`, со следующими допустимыми значениями:
  - `-r`, `-r+` – эквивалентны `DecimalUnits Yes`;
  - `-r-` &emsp;&emsp;– эквивалентно `DecimalUnits No`.

- Адреса FTN-узлов (то есть адреса с нулевым значением в поле `Point`), выводятся в таблицах и на графике без окончания `.0` для улучшения читаемости.
Пойнтовый номер выводится только если он имеет ненулевое значение. Данное изменение не затрагивает утилиту `DmpHist`.

- Сессии, закончившиеся неудачно по причине непрошедшего хэндшейка, отображаются в статистике, если мейлер записывает такие сессии в бинарный лог.
Технически, если хэндшейк не прошёл, то FTN-адрес неизвестен, и в лог записываеся адрес `0:0/0.0`. Старые версии пропускали записи с таким адресом,
хотя это неправильно. Ожидание завершения хэндшейка может быть продолжительным; сессия с неудачным хэндшейком может длиться заметное время до разрыва соединения,
но это время до сих пор никак не отображалось в статистике и не учитывалось при расчёте загрузки узла.

  Теперь неудачные сессии с неизвестным адресом отображаются в таблице сессий, в последней строке таблицы линков, в последней строке графика, а их длительность
учитывается при построении гистограмм. Для лучшей читаемости статистики, `T-Hist` и `LnkStat` вместо `0:0/0.0` выводят в качестве адреса слово `Unresolved`.
Утилита `DmpHist` такую замену не делает и выводит `0:0/0.0`.

  Если вы не хотите видеть в статистике такие сессии, то исключите адрес `0:0/0.0` из обработки:

  `Addr !0:0/0.0`

- На гистограммах уровень загрузки больше 0%, но меньше 3% отображается с помощью символа `_`. В старых версиях из-за отсутствия подходящего символа псевдографики
такой уровень загрузки либо отображался избыточно большим – как уровень 3-10%, либо не отображался вообще.

- Интервалы времени длинее, чем 23 часа 59 минут 59 секунд, выводятся в виде: число дней, число часов, число минут. Такие интервалы времени в суточной статистике
могут появляться при подсчёте суммарной длительности сессий на узлах с высокой загрузкой, поддерживающих несколько параллельных соединений. Также большие суммарные
длительности сессий могут быть в многодневной статистике, генерируемой утилитой `LnkStat`.

- В таблице сессий время начала сессий указывается с точностью до секунд (в старых версиях была точность до минут).
Время окончания сессий исключено по причине избыточности – в таблице приведена длительность сессий.

- После таблиц сессий и после таблиц со статистикой по линкам и группам выводится суммарная информация о количестве сессий, их длительности и трафике.

- При работе с бинарными логами мейлера The Brake! больше не создаётся статистика о периодах ответа на звонки, набора номеров, работы в терминале, вызовов BBS и
запуска внешних программ. Статистика создаётся только для записей о сессиях. Все остальные события пропускаются.

- `T-Hist` и `LnkStat` присваивают длительность 1 секунда сессиям, прочитанным из бинарного лога с длительностью 0 секунд. Это позволяет корректно учитывать в статистике
короткие сессии, длившиеся меньше 1 секунды. Записанное в бинарный лог нулевое значение длительности таких сессий в возникает из-за того, что интервалы времени
задаются с точностью до секунды.
 
  Утилита `DmpHist` такую корректировку длительности сессий не делает. Эта утилита продолжает работать по-старому:
выводит сырые данные из бинарных логов без какой-либо корректировки. Для сессий короче секунды утилита выведет длительность 0 секунд, как записано в бинарном логе.

- Утилита `DmpHist` выводит перед своей таблицей не только имя файла бинарного лога, но и информацию о его формате. А после таблицы – более подробную расшифровку битов
статуса сессий.

### Конфигурационный файл, значения параметров, опции командной строки

- Имена параметров в конфигурационном файле и их значения регистронезависимые за исключением имён файлов в Linux.

- В конфигурационном файле в качестве символа, начинающего комментарий, можно использовать не только унаследованный от старых версий символ `;`, но и более
привычный в linux-среде символ `#`. Особым случаем является обработка строки, содержащей параметр `Addr`. Для сохранения совместимости со старыми версиями, в которых
символ `#` использовался для задания групп адресов, такую строку можно закомментировать только целиком, поставив символ `#` перед `Addr`. Но после `Addr` символ `#`
будет уже рассматриваться как часть адреса.

- Все утилиты могут работать без конфигурационного файла, если в командной строке задан хотя бы один файл бинарного лога.
Значения параметров обработки бинарного лога определяются следующими правилами:

  - Если конфигурационный файл не указан явно с помощью опции командной строки `-c`, и в текущем каталоге не был обнаружен конфигурационный файл с именем `t-hist.ctl`,
то будут обработаны заданные бинарные логи, а все параметры, которые не были заданы другими опциями командной строки, получат значения по-умолчанию.
(Таблица со значениями параметров по-умолчанию приведена ниже.)

  - Если конфигурационный файл указан явно с помощью опции командной строки `-c`, или в текущем каталоге присутствует конфигурационный файл с именем `t-hist.ctl`,
то заданные бинарные логи будут обработаны совместно с логами из конфигурационного файла, а параметры, которые не были заданы другими опциями командной строки,
получат значения из конфигурационного файла. 

  Примеры:
  ```text
  t-hist  /var/log/fido/binlog.dat
  t-hist  /var/log/fido/binlog.dat -d-1 -t12-24 -bTIO$ -g -k -mg 
  t-hist  /var/log/fido/binlog.dat -с/home/user/fido/config/t-hist.conf -w120
  lnkstat /var/log/fido/binlog.dat -b1.9.2026 -e20.9.2026 -g 
  dmphist /var/log/fido/binlog1.dat /var/log/fido/binlog2.dat -w- -u-
  ```
- Если параметр не задан ни в конфигурационном файле, ни через опцию командной строки, то он получит значение по умолчанию, приведённое в следующей таблице:

  |    Параметр    | Значение по-умолчанию |
  | :------------- | :-------------------- |
  | `Output`       | `t-hist.out`          |
  | `LinkStat`     | `t-hist.lnk`          |
  | `SessionStat`  | `t-hist.ses`          |
  | `Date`         | сегодняшняя дата      |
  | `Time`         | `0:00:00-23:59:59`    |
  | `TimeShift`    | `0`                   |
  | `CutHistory`   | `0` (не обрезать лог) |
  | `Name`         | пустая строка         |
  | `Addr`         | `*:*/*.*`             |
  | `BinkdAborted` | `In`                  |
  | `ShowValue`	   | `Ses`                 |
  | `AdvancedCPS`, `BusyHist`, `Group`,<br>`WideScreen` | `Yes` |
  | `DecimalUnits`, `KeepAll`,<br>`MiddLine`, `NoDrawEmpty`,<br>`ProtectSummary`,`SwapInOut`, | `No` |

- Часть параметров могут быть заданы без указания их значения. Список таких параметров и значения, которые им присваиваются если они заданы без значения,
приведены в следующей таблице:

  | Допустимо задавать<br>без значения | Значение, которое будет<br>использоваться|
  | :--------------------------------- | :-------------------- |
  | `Date`                             | сегодняшняя дата      |
  | `Time`                             | `0:00:00-23:59:59`    |
  | `TimeShift`                        | `Auto`                |
  | `Name`                             | пустая строка         |
  | `Addr`                             | `*:*/*.*`             |
  | `AdvancedCPS`, `BusyHist`,<br>`DecimalUnits`, `Group`, `KeepAll`,<br>`MiddLine`, `NoDrawEmpty`,<br>`ProtectSummary`, `SwapInOut`,<br>`WideScreen` | `Yes` |

- Спецификаторы форматов, которые можно указывать при задании имён выходных файлов (в параметрах `Output`, `LinkStat`, `SessionStat` и соответствующих им
опциям командной строки `-o`, `-l`, `-e`, а также в опции `-o` утилиты `LnkStat`), приведены в соответствие со спецификаторами функции `strftime()`.
Допустимы следующие спецификаторы форматов:

  - `%Y` – год в четырехзначном формате (например, 2026);
  - `%y` – год в двузначном формате без века (от 00 до 99);
  - `%m` – номер месяца в виде десятичного числа от 01 до 12;
  - `%d` – день месяца в виде десятичного числа от 01 до 31;
  - `%j` – день года в виде десятичного числа от 001 до 366;
  - `%w` – день недели в виде десятичного числа от 0 до 6, где 0 – это воскресенье, 1 – понедельник, 6 – суббота;
  - `%u` – день недели в виде десятичного числа от 1 до 7, где 1 – это понедельник, 7 – воскресенье;
  - `%H` – час в 24-часовом формате от 00 до 23;
  - `%M` – минуты в виде десятичного числа от 00 до 59;
  - `%S` – секунды в виде десятичного числа от 00 до 59.

- Возможность обрезания бинарного лога при ненулевом значении параметра `CutHistory` реализована для логов следующих форматов/мейлеров: логи Binkd,
логи T-Mail старого и нового форматов, логи KittenMail и логи всех версий собственного формата `T-Hist`. Для остальных поддерживаемых форматов обрезание не выполняется,
а параметр `CutHistory` игнорируется.

- Утилитам `T-Hist` и `LnkStat` добавлена опция командной строки `-z`, соответствующая параметру `TimeShift`, со следующими допустимыми значениями:
  - `-z` &nbsp;&emsp;– эквивалентно `TimeShift Auto` (сдвинуть время начала каждой сессии на разность между локальным временем и UTC, которая была в момент проведения сессии);
  - `-z<N>` – эквивалентно `TimeShift <N>` (сдвинуть время начала каждой сессии на `N` часов; `N` может быть отрицательным).

- Утилита `DmpHist` не принимает во внимание параметр `TimeShift`, если он присутствует в конфигурационном файле, и выводит время начала сессий в точности так,
как оно записано в бинарном логе, без каких-либо корректировок.

- Изменена логика обработки опций командной строки `-g`, `-k`, `-n`. В старых версиях задание этих опции без следующего за ними знака `+` или `-` меняло значение
сответствующего параметра конфигурационного файла на противоположное. В новых версиях возможность инвертирования параметров убрана из-за малой востребованности,
а опция без следующего за ней знака `+` или `-` эквивалентна опции со знаком `+`.

- Опция командной строки `-h` используется для вывода справки по программе. Бинарные логи в командной строке задаются простым указанием имени файла.

- Параметры `SupportNewFormat` и `BrakeSesStat` считаются устаревшим и игнорируются при чтении конфигурационного файла.

### Правила задания и обработки адресов

- Символы `*` и `#` при задании адресов в параметрах `Addr` считаются эквивалентными. Использование любого из них делает адрес группой, порождающей для каждого конкретного
FTN-адреса отдельную строку на графике и в статистике линков (то, что в старых версиях обеспечивал символ `#`), и создающей суммарную строку на графике и в групповой статистике
для всех адресов соответствующих данной группе (то, для чего в старых версиях использовался символ `*`).

  Для сохранения совместимости со старыми версиями, символ `#` и в дальнейшем будет корректно обрабатываться при парсинге адресов. Но рекомендуется при задании групп адресов
использовать только символ `*`, поскольку он обладает очевидным смыслом символа подстановки.

- При задании адресов в параметрах `Addr` можно опускать поля адреса. Отсутствующие поля будут заменены на символы подстановки `*`. Например,

  |      Задано       |  Будет использовано |
  | :---------------- | :------------------ |
  | `Addr 2:5020/378` | `Addr 2:5020/378.*` |
  | `Addr 2:5020`     | `Addr 2:5020/*.*`   |
  | `Addr 2:`         | `Addr 2:*/*.*`      |
  | `Addr 2:5020.378` | `Addr 2:5020/*.378` |
  | `Addr 2:/378`     | `Addr 2:*/378.*`    |
  | `Addr 2:/.378`    | `Addr 2:*/*.378`    |
  | `Addr 2:.378`     | `Addr 2:*/*.378`    |
  | `Addr :5020/378`  | `Addr *:5020/378.*` |
  | `Addr :5020.378`  | `Addr *:5020/*.378` |
  | `Addr :5020`      | `Addr *:5020/*.*`   |
  | `Addr 5020/`      | `Addr *:5020/*.*`   |
  | `Addr 5020/378`   | `Addr *:5020/378.*` |
  | `Addr 5020.378`   | `Addr *:*/5020.378` |
  | `Addr /378.0`     | `Addr *:*/378.0`    |
  | `Addr 378.0`      | `Addr *:*/378.0`    |
  | `Addr 378`        | `Addr *:*/378.*`    |
  | `Addr :/.`        | `Addr *:*/*.*`      |
  | `Addr :/`         | `Addr *:*/*.*`      |
  | `Addr :.`         | `Addr *:*/*.*`      |
  | `Addr /.`         | `Addr *:*/*.*`      |
  | `Addr :`          | `Addr *:*/*.*`      |
  | `Addr /`          | `Addr *:*/*.*`      |
  | `Addr .`          | `Addr *:*/*.*`      |
  | `Addr`            | `Addr *:*/*.*`      |

- Существуют предопределённые имена адресов и групп адресов, которые можно использовать в параметрах `Addr` и опциях командной строки `-a`
(имена регистронезависимые):

  - `Addr All` – то же, что `Addr *:*/*.*`, то есть группа, охватывающая все сессии (как удачные, так и неудачные) со всеми адресами;

  - `Addr Failed` – подобно `Addr All`, но только для неудачных сессий (с неудачным хэндшейком, оборванных, завершившихся из-за какой-либо ошибки) с любыми адресами;

  - `Addr Unresolved`, `Addr Undefined`, `Addr Unknown`, `Addr None` – то же, что `Addr 0:0/0.0`, то есть любая сессия, завершившаяся неудачно на этапе хэндшейка
до того, как был определён FTN-адрес.

  Группа `Failed` включает в себя `Unresolved` / `Undefined` / `Unknown` / `None`.

  Для получения статистики только по неудачным сессиям (оборванным сессиям с известными адресами и сессиям с неопределённым из-за неудачного хэндшейка адресом)
используйте единственный параметр `Addr Failed` в конфигурационном файле или единственную опцию командной строки `-afailed` при работе без конфигурационного
файла.

  Для получения суммарной статистики по неудачным сессиям в составе общей статистики по всем сессиям, добавьте `Addr Failed` к другим параметрам `Addr`
в конфигурационном файле. Наиболее простой вариант:

  ```
  Addr All
  Addr Failed
  ```
  Если наоборот нужно исключить все неудачные сессии из статистики, используйте вариант:

  ```
  Addr !Failed
  Addr All
  ```
- Порядок задания адресов с помощью параметров `Addr` неважен. Независимо от того, в каком порядке заданы адреса и группы адресов, при генерации статистики они будут отсортированы
от менее общих к более общим. При этом исключаемые адреса и группы адресов будут размещены в начале списка, а адреса, совпадающие с исключаемой группой, удалятся. Повторные задания
одних и тех же адресов будут игнорироваться. Например, если в конфигурационном файле задано:

  ```
  Addr 2:5020/*.*
  Addr 2:5020/378.0
  Addr *:*/*.*
  Addr 2:5020/378.0
  Addr 2:*/*.*
  Addr 2:5020/1132.0
  Addr 2:5020/408.0
  Addr !2:5020/1132.*
  Addr Failed
  Addr !*:*/*.666
  Addr 2:5020/715.*
  Addr All
  Addr 2:5020/1132.0
  Addr !2:5020/408.0
  ```
  то при генерации статистики будет использоваться вот такой список адресов:

  ```
  Addr !2:5020/408.0
  Addr !2:5020/1132.*
  Addr !*:*/*.666
  Addr 2:5020/378.0
  Addr 2:5020/715.*
  Addr 2:5020/*.*
  Addr 2:*/*.*
  Addr All
  Addr Failed
  ```
  Если в конфигурационном файле не задано ни одного параметра `Addr`, то при генерации статистики будет использована группа по-умолчанию `Addr All`
(синоним группы `Addr *:*/*.*`), охватывающая все адреса. 

- Новый алгоритм просмотра списка адресов, заданных параметрами `Addr`, при генерации статистики. В старых версиях просмотр списка адресов завершался после первого
совпадения адреса сессии с одним из адресов `Addr`. В новых версиях если адрес сессии не задан как исключаемый из статистики, просмотр будет продолжаться до конца списка.
Такой алгоритм позволяет учесть сессии с отдельно заданным адресом также и в статистике по группам, к которым принадлежит адрес. Например, для списка адресов

  ```
  Addr !2:5020/1132.0
  Addr 2:5020/378.0
  Addr 2:5020/*.*
  Addr 2:*/*.*
  Addr All
  Addr Failed
  ```
  все сессии с адресом `2:5020/378.0` будут учтены не только в отдельной статистике для этого адреса, но и в групповой статистике сессий с адресами из сети `2:5020`,
в групповой статистике сессий с адресами из второй зоны и в групповой статистике сессий с любыми адресами. Кроме того, неудачные сессии с адресом `2:5020/378.0`
будут отдельно учтены в групповой статистике неудачных сессий. А сессии с адресом `2:5020/1132.0` будут полностью игнорироватся.

- Утилитам `T-Hist` и `LnkStat` добавлена опция командной строки `-a`, позволяющая задавать адреса и группы адресов для генерации статистики. Правила задания адресов
такие же, как у параметра `Addr`, включая возможность задать описание адреса. Опция может быть указана в командной строке несколько раз.
Если конфигурационный файл задан явно с помощью опции командной строки `-c`, или в текущем каталоге присутствует конфигурационный файл с именем `t-hist.ctl`,
то указанные опциями `-a` адреса будут добавлены к адресам из параметров `Addr` конфигурационного файла. Если конфигурационный файл отсутствует, но в командной строке
указан бинарный лог (логи) для обработки, то статистика будет генерироваться только для этих адресов (групп адресов).

  В следующем примере:
  ```text
  t-hist /var/log/fido/binlog.dat -a2:5020/378.* -a"2:5020\"описание группы\"" -a!failed
  ```
  опциями `-a` задано три адреса/группы (два включаемых адреса/группы и одна группа-исключение):
  ```
  Addr !Failed
  Addr 2:5020/378.*
  Addr 2:5020/*.*  "описание группы"
  ```
  При наличии в текущем каталоге конфигурационного файл с именем `t-hist.ctl`, бинарный лог `/var/log/fido/binlog.dat` и заданные адреса добавятся к параметрам
конфигурационного файла. Если же конфигурационный файл отсутствует, то будет обработан только бинарный лог `/var/log/fido/binlog.dat`, и статистика будет создана только
для трёх заданных адресов/групп.

  А задание вот таких параметров:
  ```text
  t-hist /var/log/fido/binlog.dat -c -anone
  ```
  позволит получить статистику только по сессиям с неудачным хэндшейком, записанным в бинарный лог `/var/log/fido/binlog.dat`. Здесь пустая опция `-c` предотвращает
чтение конфигурационного файла даже если он присутствует в текущем каталоге (`T-Hist` сообщит, что будут использованы значения параметров по-умолчанию). Статистика
будет создана для единственного адреса `0:0/0.0` (синонимом которого является предопределённое имя `none`), соответствующего сессиям с неудачным хэндшейком.

  Аналогичным образом опция `-a` используется в утилите `LnkStat`.

### Форматы бинарных логов, преобразования форматов, поддержка новых мейлеров

- Разработаны и полностью поддержаны всеми утилитами несколько версий нового формата бинарного лога (формат `T-Hist`) с 64-битными значениями для входящего
и исходящего трафика, позволящего корректно сохранять информацию о сессиях, во время которых было отправлено или получено более 4 гигабайт.

  Недостатком форматов бинарных логов всех мейлеров, поддерживаемых старой версией `T-Hist`, является использование 32-битных величин для записи информации о трафике.
Форматы бинарных логов мейлеров разрабатывались в эпоху dial-up, когда передать более 4 гигабайт за одну сессию было практически нереально. Но в эпоху Fido-over-IP
и высокоскоростных сетей сессия с трафиком более 4 гигабайт – обычное явление, особенно на крупных раздающих хабах.

  Разработчикам FTN-мейлеров предлагается использовать бинарные логи собственного формата `T-Hist` в своих программных продуктах. Помимо корректного сохранения
данных о сессиях с большими объёмами трафика, формат позволяет сохранять текстовые строки, которые `T-Hist` может выводить в режиме широкого экрана
справа от графика загрузки и справа от таблиц со статистикой. Также формат `T-Hist` позволяет записывать в бинарный лог отметку `Listed` для сессий,
FTN-адреса которых заданы в конфигурационных файлах мейлера или присутствуют в нодлистах, указанных в конфигурации мейлера.

  Подробно все версии собственного формата бинарного лога `T-Hist` рассмотрены в файле [FORMATS-ru.md](FORMATS-ru.md).

- Создана новая утилита: конвертер форматов бинарных логов `HistConv`. Утилита позволяет для заданного бинарного лога создать такой же лог в другом формате.
В качестве исходного может быть указан файл бинарного лога любого мейлера, поддерживаемого `T-Hist`. Формат исходного бинарного лога определяется автоматически.
Для выбора целевого формата используется опция командной строки `-f`, позволяющая указать один из следующих форматов:
  - собственный формат `T-Hist` любой из версий;
  - формат T-Mail версий 2603 и новее (новый формат T-Mail);
  - формат T-Mail до версии 2603 (старый формат T-Mail);
  - формат Binkd (старый формат T-Mail с инвертированной отметкой входящих/исходящих сессий).

  Если целевой формат не указан с помощью опции `-f`, то бинарный лог будет сконвертирован во вторую версию формата `T-Hist`.

  Для получения допустимых имён целевых форматов используйте справку по программе:
  ```shell
  histconv -h
  ```
  При конвертации в выходной лог попадают только записи о сессиях. Записи о других событиях, которые могут присутствовать в бинарных логах некоторых мейлеров
(например, записи о периодах набора номера, работе в терминале, запусках BBS и т.п.) пропускаются.

- Созданы патчи, позволяющие добавить к Binkd поддержку формата `T-Hist`. Находятся патчи в каталоге [binkd_patch](./binkd_patch). Подробнее читайте
в файле [BINKD-PATCH-ru.md](./binkd_patch/BINKD-PATCH-ru.md).

- Для использования `T-Hist` вместе с неподдерживаемыми мейлерами, сконвертируйте их логи в один из форматов, понимаемых `T-Hist`. При создании конвертеров
используйте информацию о форматах, приведённую в файле [FORMATS-ru.md](FORMATS-ru.md).
